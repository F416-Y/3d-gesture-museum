# 云墨美术馆 · 组员上手指南（认领角色后照着做）

> 本文档 = 环境准备 + Git 日常命令 + **按角色分阶段任务清单** + 验收标准。
> 读完认领自己的角色，按周执行即可。

## 一、环境准备（每人只做一次）

### 1.1 安装 Node.js

到 [nodejs.org](https://nodejs.org/) 下载 **LTS 长期支持版**（推荐 20.x / 22.x），安装时全部下一步即可。

装完在终端检查：

```bash
node -v   # 应输出 v20.x.x 或 v22.x.x
npm -v    # 应输出 10.x.x
```

### 1.2 克隆仓库

```bash
git clone https://github.com/F416-Y/3d-gesture-museum.git
# 如果 GitHub 连不上，先用下面这条（备用镜像）：
# git clone https://gitee.com/yun-yun-wai-fu/3d-gesture-museum.git

cd 3d-gesture-museum
```

### 1.3 安装依赖

```bash
npm install
```

> 依赖较大，第一次可能要 1~3 分钟。如果卡死，喊组长开代理或换 npm 镜像。

### 1.4 启动项目

```bash
npm run dev
```

终端会显示本地地址，例如 `http://localhost:5173`，浏览器打开即可。

### 1.5 配置 Supabase（有登录/收藏/评论需求时再配）

组长会提供 `VITE_SUPABASE_URL` 和 `VITE_SUPABASE_ANON_KEY`。复制模板：

```bash
cp .env.example .env.local
```

然后编辑 `.env.local` 填入对应值。不填也能跑，只是用户相关功能不可用。

## 二、Git 每日流程（最重要）

**2.1 确认推送守卫已启用**

```bash
git config core.hooksPath .githooks
```

**2.2 开工前——先同步 dev（90% 冲突都是因为这步漏了）**

```bash
git switch dev
git pull origin dev
```

**2.3 把自己的分支接到最新 dev 上**

```bash
git switch feature/你的角色名     # 见下表
git merge dev
```

| 成员 | 你的 feature 分支 | 你负责的核心文件 |
|---|---|---|
| 组员1 | `feature/scene` | `js/scene.js` |
| 组员2 | `feature/player` | `js/player.js` |
| 组员3 | `feature/gesture` | `js/gesture.js` |
| 组员4 | `feature/exhibit` | `js/config.js` + `js/exhibit.js` + `src/services/social.js` |
| 组员5 | `feature/ui` | `css/style.css` + `js/ui.js` + `src/views/*.vue` + `src/styles/vue-shell.css` |
| 组员6 | `feature/assets` | `assets/images/` + `assets/models/` + `docs/素材来源.md` |
| 组员7 | `feature/main` | `js/main.js` + `src/` 整体 + README + 部署 |

**2.4 写代码（只改你的文件）**

**2.5 提交并推送**

```bash
git add -A
git commit -m "feat(scene): 一句话描述你做了什么"
git push origin feature/你的角色名
```

**2.6 提 Pull Request：你的 feature 分支 → dev**

去 GitHub 仓库网页 → Pull requests → New PR → `base: dev` ← `compare: feature/xxx` → 简单写两句改动说明 → Create。

## 三、提交信息规范

```
类型(模块): 一句话描述
```

| 类型 | 用途 | 例子 |
|---|---|---|
| `feat` | 新功能 | `feat(gesture): 优化握拳判定阈值` |

| `chore` | 配置/杂项 | `chore: 调整 vite base 路径` |

## 四、按角色分阶段任务清单

### 组员1：3D 场景逻辑与接缝（`js/scene.js`）

> 场景**外观**（园区、主楼、连廊、灯光、挂画位置）由组长负责，坐标 v1 已定稿；
> 你负责的是**接缝**——把外观几何登记成别人能用的碰撞体、展品热点和展厅区域。
> 关键坐标见 [任务思维导图.md](./任务思维导图.md)，接缝清单见 [组员1-结对方案.md](./组员1-结对方案.md)。

#### 第一阶段：接缝登记（第 1 周结束）

| 任务 | 预期结果 |
|---|---|
| 碰撞体登记 | `obstacles` 与外观一致：前庭 → 一楼 → 西侧连廊全程不卡、不穿墙、不出围墙 |
| 门洞与台阶 | 正门门洞 x −2~2 可正常通行；两级台阶不要登记成障碍 |
| 展品热点坐标 | `registerSpot` 三处调用生成的 10 个热点，站在展品前捏合/E 弹出的是**正对**那件，不误触相邻展品 |
| 展厅区域判定 | `hallRegions` + `getHallAt`：`/#/hall/plaza`、`/#/hall/hall1`、`/#/hall/hall2` 落点正确，顶栏标签随位置切换 |
| 连廊可达性 | `/#/hall/hall2` 开局能看到展品，也能走出连廊回到前庭 |
| 新增展墙复核 | 连廊展墙 `x −12.5~−12.2` 的碰撞体（组长已加）确认不卡人 |

**验收标准**：三个展厅入口都能进且不卡人；每件展品都能用捏合/E 打开**正确**的鉴赏弹窗；帧率稳定在 40fps 以上。

#### 第二阶段：打磨 + 联调（第 2 周）

| 任务 | 预期结果 |
|---|---|
| 接缝精简 | 移除冗余碰撞体，避免玩家被小物件绊住 |
| 素材适配联调 | 组员6 替换贴图/glb 后比例正确、模型不悬空，必要时微调热点半径 |
| 性能检查 | drawCalls 不过高；必要时合并静态几何体 |
| 复核外观改动 | 组长每次改外观后，接缝坐标跟着复核（你是 `scene.js` 的 owner，PR 上要 review） |

## 六、常见问题速查

**Q：我不小心改了别人的文件怎么办？**

A：先别提交。用 `git checkout 文件名` 恢复成仓库版本，再重新改自己的文件。

**Q：npm install 报错 / 卡住？**

A：让组长检查代理，或换 npm 镜像：

```bash
npm install --registry=https://registry.npmmirror.com
```

**Q：我按 W 走不动？**

A：先看画面右下角 hall-label 是否显示，再看浏览器控制台有没有红色报错。最常见原因是 `MediaPipe` 加载失败导致 `main.js` 初始化中断——刷新重试即可。

**Q：收藏/评论功能显示「未配置 Supabase」？**

A：你还没填 `.env.local`，或者填错了。找组长要正确的 Project URL / Anon Key。

**Q：我要临时看别人的分支怎么切？**

A：可以 `git switch feature/xxx` 查看，但**不要在自己的分支 merge 别人的分支**，一切以 dev 汇总为准。
