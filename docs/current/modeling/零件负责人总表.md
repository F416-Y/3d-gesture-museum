# 零件负责人总表

这份表是当前唯一的零件建模分配依据。每个零件只有一个主负责人；组长除参考图、坐标尺寸和验收外，承担 4 个指定零件的 Blender/GLB 建模。其他成员只修改自己负责的 GLB 和任务单允许的内饰 HTML。

## 使用规则

1. 先打开“参考图路径”，再在 Blender 里建模或清理现有模型。
2. `已有 GLB / 待验收` 表示文件已经在仓库里，但仍要由负责人完成方向、尺寸、原点、材质和 360° 检查。
3. `待生成` 表示 manifest 有定义但当前 `assets/models/parts/opt/` 没有对应文件，负责人需要生成并导出。
4. 参考图是视觉约束，真实尺寸以 `assets/models/parts/parts-manifest.json` 的 `sizeM` 为准；桥、湖和展厅坐标以 `docs/current/scene/` 下坐标文档为准。

> **重要：整体展厅效果图不等于零件参考图。** `assets/reference/exhibition/current/` 只用于空间风格和内饰氛围；单个零件的形状、尺寸和可替换关系必须同时核对 `parts-manifest.json` 与 `assets/models/parts/ref/`。两者冲突时，先暂停建模并反馈，不得直接按新效果图改原零件。
5. 组员 1 不承担建模，组长承担 `gate-tower`、`steps`、`camphor`、`bush` 四个指定零件；组员 2 只负责第三人称/漫游交互和人物模型筛选；远景层交给组员 6。

## 每个负责人交付什么

- **组员 3**：山水内饰 HTML、`roof-tile`、`column`、`lattice-window`、`skylight`、`painting-frame`。
- **组员 4**：人物内饰 HTML、`horse`、`stone-lion`、`bronze-ding`、`warrior`、`pedestal`。
- **组员 5**：花鸟内饰 HTML、`door-column`、`door-leaf`、`door-canopy`、`wall-pillar`、`back-wall`、`long-table`、`bookshelf`。
- **组员 6**：花鸟植被、庭院植被和远景层，包含 `bamboo`、`tree`、`willow`、`banana`、`grass-clump`、`grass-tuft`、`rock-boulder`、`grass-patch`、`dead-trunk`、`fir-tree`、`taihu-rock`。
- **组员 7**：参考图、坐标验收，以及 `gate-tower`、`steps`、`camphor`、`bush` 四个指定零件。
- **组长**：文创内饰 HTML（`public/wenchuang.html`），以及统一参考图、尺寸/坐标验收；不接手成员 8 的展示架、宫灯 GLB。
- **组员 8**：书斋内饰 HTML及 `stool`、`bench`；文创展示架和宫灯 `display-shelf`、`lantern`。

## 远景层负责人

远景层由**组员 6**负责，和组员 2 的漫游逻辑解耦。范围只包括远山、云雾、树线和 360° 环视连续性，不包括桥、中心湖、建筑主体或任何内饰。

- 参考图：`assets/reference/exhibition/shanshui-design.png`、`assets/reference/exhibition/perspective.png`、`assets/reference/exhibition/design-overview.png`
- 坐标依据：`docs/current/scene/外观原型-坐标对接表.md`、`docs/current/scene/江南院落平面-坐标版.md`
- 交付位置：远景模型/贴图放到任务单指定的 `assets/` 子目录；页面接入只通过负责外景入口的 PR 完成，不直接修改 `index.html`。
- 验收：前、左、后、右四个方向均有连续远景；云雾不出现明显矩形白边；不遮挡建筑，不与桥湖重叠，第一人称和第三人称都能正常观看。

## 通用验收

每个零件必须附：参考图路径、Blender 360° 旋转截图、尺寸/原点说明、GLB 文件路径、对应页面截图。不能只说“模型已完成”。
