# 运行时稳定性优化说明

## 已修复的根因

开场“整馆粒子采样”等待 `MuseumExteriorSlots.ready` 时，每次回调都会对同一个 Promise 再注册一次 `.then()`。资源加载完成后形成无限微任务循环，导致页面持续卡死并最终崩溃。现在改为只等待一次，并等待静态合批完成后才开始采样。

## 场景预算

优化前程序化场景：

- 4,687 个独立 Mesh
- 4,660 个独立 Geometry
- 3,443 个阴影投射物
- 3,576 个阴影接收物

新增 `js/static-batcher.js` 后，同材质、同属性布局、同阴影设置的静态 Mesh 会合并：

- 程序化场景：4,679 → 65 个 Mesh，30 个批次
- 加载完整 GLB 场景：5,980 → 约 318 个 Mesh，约 113 个批次
- 阴影投射物：3,443 → 约 274 个

## 其他稳定性措施

- 摄像头手势默认关闭，避免 MediaPipe 与 3D 主场景同时占用 CPU/GPU；用户仍可手动开启。
- 开屏动画期间暂停主场景渲染，进入博物馆后再启动。
- 开场 WebGL 上下文和隐藏视频在退场后释放。
- 按屏幕尺寸、像素比、内存和 CPU 核心数选择高/中/低画质。
- 连续低帧率时自动降低渲染比例并关闭阴影。
- 低画质设备保留程序化建筑与展品占位，不加载高面数 GLB；可手动使用 `?quality=low` 强制低画质。
- 白昼隐藏不亮的灯笼 PointLight，减少片元着色开销。
- 监听 `webglcontextlost` 并自动进入低负载恢复模式。

## 压力测试

真实 Edge、1280×720、无头软件渲染、连续按住 W 漫游：

- 高画质：稳定约 36–37 FPS，无崩溃、无 WebGL 上下文丢失
- 低画质：稳定约 59–60 FPS，无崩溃
- 场景内约 14M 三角形、约 146 次绘制调用（高画质完整 GLB）
- 低画质约 316K 三角形、约 52–60 次绘制调用

诊断命令：

```bash
node scripts/diagnose-runtime.mjs "http://127.0.0.1:4173/?quality=low" 20
```

场景预算命令：

node scripts/analyze-scene-budget.mjs
