# AI + Hyper3D + Blender 建模指导流程

本页是所有需要建模成员的统一操作手册。每个成员的指导文档只允许在本页流程范围内操作，并以自己的零件负责人表为准。

## 0. 先确认边界

1. 先打开 `docs/current/modeling/零件负责人总表.md`，确认自己负责的零件、参考图、`sizeM`、输出路径。
2. 只改任务卡允许的 GLB 或独立内饰 HTML；不要修改 `index.html`、公共 `js/**`、公共 CSS 或其他成员的页面。
3. 一次只处理一个零件。先把小零件做通，再组合到展厅，禁止直接拿整包古镇模型覆盖现有场景。
4. 所有尺寸以 `assets/models/parts/parts-manifest.json` 和 `docs/current/scene/` 坐标文档为准；AI 图只负责外观参考，不替代尺寸。

## 1. AI 生成建模前的准备

1. 把实际参考图放到 `assets/reference/` 对应子目录，并在任务卡里写相对路径。
2. 用 AI 先整理建模 brief：用途、正面方向、长宽高、材质、必须保留的细节、不能出现的元素。
3. 提示词必须写清楚“单独物件、无背景建筑、正交三视图/多角度、尺寸标注”；不要只说“生成一个古风建筑”。
4. 生成结果只用于确定形体和材质方向。若出现多余建筑、桥湖方向错误、底座悬空、比例失真，立即重生成，不拿错误图做模型依据。

## 2. Hyper3D 生成初稿

1. 进入 Hyper3D/Rodin，选择 image-to-3D；优先上传正视图或立体参考图，必要时再补侧视图。
2. 物件命名使用英文短名，例如 `display-shelf`、`stone-lion`、`gate-tower`；不要使用中文文件名作为导出名。
3. 生成后先看四件事：长宽高比例、正面朝向、底面是否完整、是否混入地面/墙体/灯光/相机。
4. 只保留一个主体版本。不要把多个 Hyper3D 结果叠加成“看起来更完整”的模型；这会导致重复几何和碰撞错误。
5. 导出 GLB 前记录 Hyper3D 生成版本、参考图路径和已知缺陷，写进 PR 描述。

## 3. Blender 清理与精细化

1. Blender 导入 GLB 后，删除相机、灯光、地面、重复物件和无关建筑；Outliner 只保留当前零件。
2. 设为 Z-up，确认项目正面方向；桥、湖、建筑的方向必须以坐标文档为准，不能凭视角猜。
3. 用 `N` 面板检查 Dimensions，按 `sizeM` 设置真实尺寸；再 `Ctrl+A → Rotation & Scale`。
4. 把原点放在底部中心；门扇放在铰链边；桥和建筑最低点贴地，不能悬空、插地或倒置。
5. 修复法线、孤立点、非流形边和破面；删除完全不可见的内部面，但保留近景会看到的门缝、瓦垄、窗棂、护栏和石材分缝。
6. 材质只保留项目需要的材质槽；贴图使用相对路径，贴图尺寸优先 1K/2K，不要把超大原图直接塞进网页。
7. 近景零件优先做轮廓和接缝，远景零件优先控面数；不要为了“精细”无限加面。
8. 命名对象和材质：`<id>_mesh`、`<id>_mat`；一个零件一个主对象，便于网页定位和替换。
9. 先保存 `.blend` 工作文件到个人临时目录，再导出 `assets/models/parts/opt/<id>.glb`；不要覆盖别人的 GLB。
10. 在 Blender 中旋转 360°检查：正面、背面、左右、顶部、底部各看一次，并截图记录。

## 4. 从小零件到大型展厅的顺序

### A. 小零件

门柱、灯笼、方凳、展示架、窗格、石块等：先做单体 → 检查尺寸/原点 → 导出 GLB → 在对应 HTML 中放置 → 再做材质细节。

### B. 中型组合件

门楼、展台、长案、拱桥等：先拆成可替换部件，再组合验证接缝；桥必须先核对方向、桥长、桥宽、湖岸落点，不能直接按 AI 图拉伸。

### C. 大型展厅

先确定墙体、门、地面和主要机位，再放家具和展品，最后补灯光、植物和装饰。内饰 HTML 必须独立运行，门关闭后不能透出外景；验收时从入口、中心、展品近景三个机位截图。

## 5. 网页接入与验收

1. 只在自己负责的 `public/*.html` 中接入模型路径、位置、旋转和缩放。
2. 先用固定机位确认模型，再测试漫游；不要在模型未对齐前用自由视角掩盖问题。
3. 检查：模型不悬空、不穿地、不倒置、不重复；贴图加载；碰撞/通行；不遮挡画作和入口。
4. 提交三类证据：Blender 360° 截图、网页固定机位截图、尺寸与路径记录。

## 6. Git 与 PR

```powershell
git switch main
git pull
git switch -c feature/<模块>-<子任务>-<组员序号>
git status
git add <自己负责的文件>
git commit -m "feat(<模块>): 完成<零件或展厅>建模"
git push -u origin feature/<模块>-<子任务>-<组员序号>
```

每个子任务一条分支、一个 PR，base 固定为 `main`。不要直接在 `main` 提交，也不要把其他成员的文件顺手改进 PR。

## 7. 常见错误

- Hyper3D 生成了整座建筑：回到单零件输入，不要在 Blender 里硬删到失控。
- 物件方向反了：先在 Blender 旋转并应用，再导出，不在 HTML 里用大角度补救。
- 模型大小不对：重新核对 `sizeM`，不要用浏览器缩放猜尺寸。
- 贴图丢失：检查 GLB 内嵌贴图或相对路径，浏览器 Network 面板不能有 404。
- 参考图和实际坐标冲突：坐标文档优先，暂停建模并在 PR 中标出冲突点。
