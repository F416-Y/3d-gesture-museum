## 一、要改什么

`js/config.js` 两个数组：`halls`（3 → 8 个）与 `exhibits`（10 → 12 件），**字段结构不变**：

```js
// halls 元素：{ id, name }
// exhibits 元素：{ id, type, hall, title, artist, dynasty, era, medium, collection, intro, appreciation }
// type 取值：painting / sculpture / artifact
// id 规范：拼音小写、无连字符、与素材文件名一致（例：xishanxinglvtu）
```

## 二、halls 目标（8 个）

| id | name（写进 config，顶栏与导航直接显示） | 完整名（只用于文档/答辩，**不要**写进 config） |
|---|---|---|

| `hall0` | 序厅 | 序厅 |
| `courtyard` | 庭院 | 中央庭院 |
| `hall1` | 山水 | 山水画展区 |
| `hall2` | 花鸟 | 花鸟画展区 |
| `hall3` | 人物 | 人物画展区 |
| `hall4` | 书斋 | 书斋 · 茶室 |
| `hall5` | 文创 | 文创区 · 临帖休憩 |

> **为什么必须用短名**：顶部导航与顶栏标签会把这 8 个名字**横排**显示。像「文创区 · 临帖休憩」这种 8 字名，8 个并排在 1440px 下就排不下、768px 必爆版。所以 `name` 一律 **2~3 字**，完整名只写在文档与答辩材料里。
> **结构保持不变**：`halls` 元素仍然是 `{ id, name }`，**不要新增字段**（加了会连锁影响 `js/ui.js` 与 `src/App.vue` 的渲染）。
> `id` 必须与 [江南院落平面-坐标版.md](./江南院落平面-坐标版.md) §二 完全一致。

## 二之二、`player.startPos` 也要一起改（同一个文件）

| 位置 | 现在 | 改成 |
|---|---|---|
| `config.js` 的 `player.startPos` | `[0, 0, 26]` | **`[0, 0, 38]`** |

**原因**：`(0, 26)` 落在 `hall0` 序厅（z 24~34）范围内，玩家一出生就会被判定成「序厅」而不是「前庭」。

**注意两处必须一致**：`src/views/MuseumView.vue` 里有一份镜像的落点表（组长的文件），组长已同步改成 `(0, 38)`——你这边改完两边就对齐了。

顺带把那条过时注释也换掉：现在写的是「出生点（前庭中轴，能一眼看到门柱 → 铜奔马 → 主楼立面）」，**主楼在新方案里已经拆了**，建议改成：
`// 出生点（前庭中轴，位于 hall0 序厅之外，避免出生即判「序厅」）`

## 四、验收标准

1. `node scripts/smoke-scene.mjs` 通过（它会校验**每个热点 id 都在 config 里存在**，写错 id 立刻报错）
2. `npx tsc --noEmit` 与 `npm run build` 通过
3. `halls` 恰好 8 项、`exhibits` 恰好 12 项，`id` 无重复、全小写拼音
4. 每件展品的 `intro` 不少于 80 字、`appreciation` 不少于 120 字
5. `halls` 的 `name` 一律短名（2~3 字：前庭 / 序厅 / 庭院 / 山水 / 花鸟 / 人物 / 书斋 / 文创），完整名不写进 config
5. 提 PR：base = `main`，标题写明「六厅结构 + 12 件展品」，**描述里列出所有新增 id**（我们其他人要照着挂画）

- **改 id = 全组连锁**（挂画位置、热点、弹窗、收藏都读它）。所以：**先把 id 定下来发群里**，再填文案，避免我们挂错画。
