# 流程速查卡（照着做，不会错）

> **只看这一页就能开工。** 原理和细节见 [Git-快速上手.md](./Git-快速上手.md)。
> 卡住了：先看第 5 节「出错了怎么办」，还不行就在群里 @组长。别自己硬猜。

---

## 1. 三条铁律

1. **永远不要在 `main` 上直接改代码**（本地钩子和 GitHub 都会拦，白干）。
2. **一个子任务 = 一条分支 = 一个 PR**，PR 里只干这一件事，做完就合并、合并后删分支。
3. **只有组长点 Merge**。提完 PR 等通知，**不要自己合**。

---

## 2. 开工：三行命令（每次只改分支名）

```bash
git switch main
git pull origin main
git switch -c feature/scene-collision-1     # ← 换成 2.3 节对照表里属于你的那条
```

> 分支名对照表在 [组员上手指南.md](./组员上手指南.md) 的 **2.3 节**，30 条都在里面。
> 表里没有的活，按规则现起：`feature/<模块>-<子任务>-<你的序号>`。

---

## 3. 干活 → 提交 → 推送

```bash
git status                    # 先确认：只改了自己负责的文件
git add -A
git commit -m "feat(scene): 登记前庭与围墙的碰撞体"
git push -u origin feature/scene-collision-1
```

**提交信息格式**：`类型(模块): 一句话`
类型用 `feat` / `fix` / `style` / `docs` / `asset` / `chore`，模块用文件名去后缀（`scene` / `player` / `gesture` / `exhibit` / `ui` / `assets` / `main`）。

---

## 4. 提 PR：五步

1. 打开仓库网页 → **Pull requests** → **New pull request**
2. **base 选 `main`**（默认就是 `main`，不用改）
3. 标题写清子任务，描述里写：**改了什么 / 怎么自测的**
4. 把 PR 模板里的勾选项逐个勾完（没做的就是没做，别硬勾）
5. 点 **Create**，然后**等两件事**：CI 变绿 + 组长 Approve

> CI 会跑两项：**引擎冒烟测试**和**生产构建**。红了不要催组长，先自己看日志修。

---

## 5. 出错了怎么办（对号入座）

| 症状 | 原因 | 怎么办 |
|---|---|---|
| `git push` 被拒，提示不允许推 main | 你在 main 上改了代码 | 先 `git switch -c feature/xxx-你的序号`（改动会跟着过去），再 push |
| push 提示需要先 pull | main 上有别人的新提交 | `git switch main && git pull`，然后 `git switch 你的分支 && git merge main` |
| 出现 `CONFLICT` | 你和别人改了同一处 | 打开冲突文件，改好内容、删掉 `<<<<<<<` `=======` `>>>>>>>` 三行标记 → `git add 文件` → `git commit`；拿不准就 @组长 |
| CI 报「冒烟测试未通过」 | 场景数据结构写坏了 | 看日志里那行具体问题（例如「热点 id 在 config.js 里不存在」），修完再 push |
| CI 报「生产构建」失败 | 语法错误或缺文件 | 本地跑 `npm run build`，看报错行 |
| 忘记删分支了就提了新 PR | 一分支多任务 | 关闭 PR、删分支，按子任务重新开分支 |
| 不确定分支名 | —— | 别猜，去 2.3 节对照表找；找不到就 @组长问一句 |

---

## 6. 合并之后

- 组员：`git switch main && git pull` → 删掉自己那条分支（`git branch -d 名字` + `git push origin --delete 名字`）→ 开下一个子任务。
- 组长：合并前本地跑一遍 `node scripts/smoke-scene.mjs` 和 `npm run build`；里程碑打 tag（`git tag -a v0.2-week1 -m "..."` → `git push origin v0.2-week1`）。

---

## 7. 现在该干什么

1. 找到 [组员上手指南.md](./组员上手指南.md) **2.3 节**里你的第一个子任务 → 记下分支名
2. 按第 2 节三行命令开工
3. 干完按第 3、4 节提交并提 PR
