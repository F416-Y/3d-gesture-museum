## 一、模块调用关系（代码实测）

```
                 ┌──────────────┐
                 │  config.js   │  ← 唯一数据源（展品 id / 标题 / 朝代 / 展厅表）
                 └──────┬───────┘
      ┌─────────────┬───┴────┬─────────────┬──────────────┐
      ▼             ▼        ▼             ▼              ▼
  scene.js     exhibit.js  gesture.js    ui.js      Vue 壳(router/social)
      │             │         │            ▲              │
      ▼             │         │            │              │
  player.js         │         │            │              │
      │             │         │            │              │
      └──────┬──────┴─────────┴────────────┴──────────────┘
             ▼
          main.js  ← 启动顺序：UI → Scene → Player → Exhibit → Gesture

**读出来的三条硬事实**

1. `config.js` 是唯一的根：改一个展品 `id`，会同时打到 scene（挂画/热点）、exhibit（拾取）、ui（弹窗）、social（收藏）四处。
2. `scene.js` 的 `obstacles / spotMeshes / hallRegions` 是三个跨模块出口，分别喂给 player、exhibit、player+路由。
3. 所有模块的 `init` 都在 `main.js` 里按序调用——**任何一个模块的 init 抛错，整个页面白屏**。

## 二、接口契约表（谁给谁什么）

| 接口 | 提供者 | 消费者 | 数据结构 / 语义 |
|---|---|---|---|
| `MuseumScene.obstacles[]` | 场景 | player.js 碰撞 | `{type:"rect",x0,z0,x1,z1}` 或 `{type:"circle",x,z,r}`，单位 = 世界米 |
| `MuseumScene.getHallAt(x,z)` | 场景 | player.js (`:47`,`:86`) | 返回 `"plaza" / "hall1" / "hall2"` 或 `null` |
| `MuseumScene.spotMeshes[]` | 场景 | exhibit.js 拾取 | `{exhibitId,x,y,z,radius}`，radius 为触发半径 |
| `MuseumConfig.exhibits[]` | 数据 | scene / exhibit / ui / social | `id`（唯一键）、`title`、`dynasty`、`author` 等 |
| `MuseumPlayer.getPosition()` | 玩家 | exhibit.js 距离判定 | `THREE.Vector3`（相机位） |
| `MuseumPlayer.teleport(x,z,yaw)` | 玩家 | Vue 路由 | 直接落点，绕开碰撞 |
| `MuseumUI.showExhibit(ex)` | UI | exhibit.js | 传入完整展品对象，UI 不再查 config |
| `MuseumGesture.getState()` | 手势 | main.js 输入合成 | `{forward,turn,…}`，与键盘在 `composeInput` 合并 |

> 契约原则：**提供方只读导出，消费方绝不写别人的状态**；改结构必须双方同步改 PR 描述。

## 四、关键路径（迟一天，全会晚一天）

```
T-0.2 展品 id 定稿
   → T-1.1 场景外观坐标冻结      ← 本次已产出 v1（2026-09-21）

         → T-2.1 漫游碰撞 + T-4.2 热点拾取

               → T-ALL 联调 → T-7.4 部署

## 五、可并行 / 必须串行

| 关系 | 结论 | 原因 |
|---|---|---|
| T-1.1 外观 ∥ T-0.2 展品 id | **可并行** | 外观只需展品 id 来决定挂哪几幅，可先按现有 10 件排布 |

| T-1.1 → T-1.2 | **必须串行** | 碰撞体与热点坐标直接取自外观几何 |
| T-6.1 素材 ∥ T-1.2 接缝 | **可并行** | 素材只换贴图/模型，不动坐标；但改模型尺寸后要回看接缝 |
| T-2.1 ∥ T-4.2 | **可并行** | 两者都只读 `MuseumScene` 的导出，互不写 |
| T-7.1 接线 | **必须最后** | 依赖所有模块的 `init` 签名不变 |

## 九、一句话总结

**根在 `config.js`，扣在 `scene.js`，出口在 `main.js`。**
- `config.js` 定「有什么」→ 必须最先冻结
- `scene.js` 定「在哪、怎么挡」→ 是当前关键路径
- `main.js` 定「怎么跑」→ 必须最后接线
